# VARṆA-7 і PRĀṆA-14 — мої дві версії кодування звуків

Дві самостійні альтернативи наявним `UPC-7` і `UPC-14 v2` з репозиторію
`shiva-sutras`. Це не заміна й не «патч» до них — це інша філософія дизайну,
яку можна порівняти з існуючою. Усе нижче — інженерні кодеки, не твердження
про Паніні.

| | 7 біт | 14 біт |
|---|---|---|
| назва | **VARṆA-7** | **PRĀṆA-14** |
| роль | identity-кодек (кожен звук = одна клітинка) | фонетичний код (координати звука) |
| головна ідея | регіони за **зусиллям (prayatna)**, не за «варга/не-варга/голосний/знак» | поля **effort-first**; `savarṇa` — **одна бітова маска** |
| модуль | `varna7.py` | `prana14.py` |

---

## VARṆA-7 — 7-бітний кодек за зусиллям

Наявний `UPC-7` ділить 7 біт за *категорією* (`varga` / `non-varga` / `vowel` /
`sign`). Я ділю за **чотирма внутрішніми зусиллями (prayatna)**, які Kāśikā
називає на сутрі 1.1.9:

| регіон | зусилля | що там | використано |
|---|---|---|---|
| `00` SPARSA | spṛṣṭa (повний дотик) | 25 приголосних-варга | 25 (7 зарезервовано) |
| `01` ANTAS | īṣat-spṛṣṭa + ūṣman | 4 півголосних + 3 шиплячих + h | 8 (24 зарезервовано) |
| `10` SVARA | vivṛta (розкрив) | голосні: рядок(3) + nasal + length | 28 (4 зарезервовано) |
| `11` SAMJNA | — | it-маркери / знаки / розширення | 32 названі |

```
CCxxxxx
^^ 2-бітний регіон
   xxxxx = 5-бітний payload (зміст залежить від регіону)
```

`payload`:
- SPARSA: `place*5 + member` (місце 0..4, член 0..4);
- ANTAS: `place(3) | kind(2)` (kind: 0/1 = фрикативні → ūṣman; 2/3 = сонорні → īṣat-spṛṣṭa);
- SVARA: `row(3) | nasal | length` (рядки a i u ṛ ḷ e o; рядок 7 зарезервовано);
- SAMJNA: `index(5)`.

`VARṆA-7` — це identity-кодек: SLP1-написання звуку round-trip'иться, клітинки
не перетинаються, а `savarṇa` доступний і як функція (`savarna_key`).

**Чесна межа.** На 7 бітах для рядків e/o є лише біт довжини, тож `e` й `ai`
(а також `o` й `au`) ділять один рядок і розрізняються лише бітом довжини —
рівно як у `UPC-7`. Через це `savarna(e, ai)` у VARṆA-7 дає `True`, хоча
Kāśikā їх savarṇa не називає. Це не недогляд, а властива межа 7 біт: `a`/`ā`
мають бути savarṇa, а `e`/`ai` — ні, і один біт довжини не може розрізнити ці
два випадки. Саме тому 14-бітний код має окремий біт `wide`.

## PRĀṆA-14 — 14-бітний код із маскою savarṇa

`UPC-14 v2` впорядковує поля place-first і тримає voice та aspiration окремо;
`savarṇa` там — функція. Я впорядковую поля **effort-first** і пакую
(voice, aspiration) в одне панінійське поле `prāṇa`:

```
code (14) = meta(1) | effort(2) | wide(1) | place(5) | nasal(1) | prāṇa(2) | length(2)
              13        12-11      10        9-5         4         3-2        1-0

effort  0 spṛṣṭa  1 īṣat-spṛṣṭa  2 ūṣman  3 vivṛta
wide    0 звичайний  1 широкий  (розрізняє e/o від ai/au)
place   булева ґратка на 5 атомах: горло / піднебіння / ретрофлекс / зуби / губи  (join = OR)
nasal   ніс, окремий атом від місця (1.1.8)
prāṇa  0 aghoṣa-alpa  1 aghoṣa-mahā  2 ghoṣa-alpa  3 ghoṣa-mahā
length 0 короткий  1 довгий  2 pluta
```

42 звуки Шіва-сутр **виводяться з одного насіння `k`** типізованими ребрами
(`asp`, `voice`, `nasal`, `shift`, `lift`, `widen`, `join`, `long`) — жоден звук
не заданий списком ознак.

### Що це додає

`effort(2) + wide(1) + place(5)` — це **вісім суміжних бітів** (5..12). Тому вся
перевірка 1.1.9 стискається в одну операцію:

```python
savarna(a, b)  ==  (a & 0x1FE0) == (b & 0x1FE0)
```

І саме тому потрібен біт `wide`: він єдиний, що кладе `e` й `ai` в різні маски
(їх 1.1.9 не називає savarṇa), тоді як `a` й `ā` лишаються в одній масці
(їх 1.1.9 savarṇa називає). Біт довжини цього не вміє — і саме тут 14 біт
виграють у 7.

### Запити як операції над кодом

| правило | як запит |
|---|---|
| pratyāhāra | інтервал шляху сутр |
| 1.1.9 savarṇa | маска `& 0x1FE0` |
| 6.1.101 dīrgha | два savarṇa простих голосних → довгий |
| 6.1.87 / 6.1.88 guṇa, vṛddhi | об'єднання місць; vṛddhi ще й `widen` |
| 1.1.50 sthāne'ntaratamaḥ | найближча вершина (place першим; нічия → `Ambiguous`) |
| 6.1.77 yaṇ / 8.2.39 jaś | той самий `nearest` з іншою цільовою множиною |

## Порівняння з наявними кодеками

`python3 compare_to_upstream.py [шлях-до-shiva-sutras/prototype]`

Фактичні результати прогону:

- **Інвентар.** PRĀṆA-14 матеріалізує 47 звуків (42 + 5 довгих голосних);
  `UPC-14 v2` тримає 42 і довгі виводить на вимогу (`dirgha`). Множини міток
  збігаються.
- **guṇa / vṛddhi.** `guṇa(a,i)=e`, `guṇa(a,u)=o`, `vṛddhi(a,e)=ai`,
  `vṛddhi(a,o)=au` — збіг з `UPC-14 v2` в усіх чотирьох.
- **pratyāhāra.** `ac`, `hal`, `aN`, `haY` — інтервали збігаються з v2
  (той самий порядок сутр).
- **savarṇa (20 пар).** Усі три кодеки збігаються з очікуваним прочитанням
  **скрізь, крім двох пар**: `e~ai` і `o~au`, де VARṆA-7 дає `True`
  (7-бітна межа вище), а `UPC-14 v2` і PRĀṆA-14 — `False`.
- **Маска.** `savarna(a,b) == ((a & 0x1FE0) == (b & 0x1FE0))` — істина для всіх
  47×47 пар у PRĀṆA-14. Ця властивість є тільки в моєму дизайні.

## Артефакти

- `varna7-table.tsv` — повна таблиця 128 клітинок, **згенерована** скриптом
  `varna7_table.py` (не редагується вручну): стовпці `bits hex region payload
  status name sa-slp1`. 93 клітинки `assigned`, 35 `reserved`; reserved-клітинка
  не має написання й має канонічне ім'я `reserved.<region>.<payload>`.
- `varna7-table.sha256` — пін таблиці. Споживач має пінити цей хеш і
  перегенеровувати проти нової таблиці, а не копіювати її вручну.
- `prana14.dot` — граф виведення 42 звуків із насіння `k` (Graphviz; звуки —
  вершини, типові ребра — стрілки).

```sh
python3 varna7_table.py --write     # перегенерувати varna7-table.tsv
python3 varna7_table.py --check     # exit 1, якщо таблиця застаріла (для CI)
python3 varna7_table.py --sha256    # надрукувати пін
python3 prana14.py --dot > prana14.dot
```

Поточний пін: `3b38266f4a6587fdb7c7a736aec8b26b62cf3c976695a2b0135f00496e3424c7`.

## Межі (те, що ці кодеки НЕ доводять)

- Ознаки звуків (місце, зусилля, дзвінкість, придих) — моделювальний вибір за
  традиційною класифікацією, перевірений лише на внутрішню несуперечність,
  не проти первинного фонетичного джерела.
- Порядок сутр — один канон; результат про інтервали нічого не каже про те,
  чому саме такий порядок.
- Не покрито: наголос, повний порядок Aṣṭādhyāyī (конфлікт правил, 1.4.2),
  pluta-вжиток, будь-який текст поза 42 звуками, апаратна упаковка.
- Це інженерний кодек. Він не є свідченням про те, як працював Паніні, і не
  змінює переданий канон Шіва-сутр.
