## Ідея

Два незалежні свідки судять спорідненість українського та санскритського
слова; вердикт COGNATE — тільки коли обидва згодні:

```text
uk слово ──┬──→ BGE-M3 ──→ meaning (семантика)  ──┐
           │                                       ├──→ combined → hypothesis
           └──→ UPC-8 ──→ sound (фонетика) ───────┘
```

## Результати v1 — ЧЕСНИЙ НЕГАТИВНИЙ РЕЗУЛЬТАТ

Прогін проти golden set (13 підтверджених пар):

```text
Baseline (meaning only):      12/13 top-1 hits
v1 naive fusion (geomean):     1/13 top-1 hits   ← ГІРШЕ У 12 РАЗІВ
```

| uk | sa | sound | meaning | verdict |
|---|---|---|---|---|

відстанню по UPC-8 кодах руйнує точність семантичного свідока.

## Діагноз: чому sound-witness провалився

Споріднені слова **не звучать однаково** — вони мають **системні
звукові відповідності**: ПІЄ `*ḱērd` дало санскр. `hṛdayam` (ś/h-шар)
і слов. `серце` (с-шар). Коди різні — коріння спільне.

Три помилки v1:
1. Повні слова замість приголосного скелета (голосні зникають першими)
2. Точні коди замість артикуляційної близькости (`*ḱ` vs `с`:
   різні коди, близькі місце/спосіб — PVC-16 вектори це бачать!)
3. Немає таблиці системних відповідностей як даних

## План v2 (зафіксовано, не реалізовано)

1. **Приголосний скелет**: порівнювати лише згодні (класика
   компʼютерної історичної лінгвістики)
2. **Артикуляційна відстань через PVC-16**: `ḱ`↔`с` близькі за
   місцем/способом навіть з різними UPC-8 кодами
3. **Sound-correspondence table як дані**: `extensions/sound-correspondences.yaml`
   — `*ḱ↔ś/s`, `*bʰ↔b/h`, ... (та сама філософія «дані замість магії»)
4. Ф'южн: mean(sound_v2, meaning), перевірка на тому ж golden set.
   Цільовий критерій прийняття: **≥ 12/13 top-1** (не гірше за baseline),
   інакше v2 теж REJECTED.
