**Evidence from the UPC-14 lab (juv4uk/shiva-sutras, experimental, not authority).** A comment for #1961 only; no SENS code touched.

What UPC-14 v2 is: 42 Śiva-sūtra sounds as vertices of a graph, identity = a 14-bit code whose fields are the vertex coordinates (place lattice, nasal, aperture path, length path, voice, aspiration, meta). Relevant to the premises here:

1. **Generator over registry, and it is falsifiable.** The whole inventory is derived from one seed (`k`) by typed edges (`asp`, `voice`, `nasal`, `shift`, `lift`, `join`, `long`); no sound is listed with its features. Executable checks: 42 distinct valid codes; every classical pratyāhāra equals an interval of the sūtra path (43/43 of an external oracle, 42/42 of the project's YAML after fixing 3 wrong entries); savarṇa (1.1.9) is one bit mask over the code (`0x1F70`), identical to the relation function on all 47×47 pairs.
2. **Typed relations kept apart.** Sūtra order (path/interval), coordinate mask (savarṇa), nearest-vertex query (1.1.50 substitution) and derivation edges are separate relations; none is read off code geometry.
3. **Consistent with your negative result on global Hamming-1 adjacency.** Among the 42 codes there are 36 pairs at Hamming distance 1 (of 861); only 27 of them are typed derivation edges, and 12 of the 39 single-parent typed edges are *not* Hamming-1 (distances 2 and 3: `shift`, `lift3`, some `lift1`). So code adjacency neither contains nor equals the semantic edges here.
4. **Identity ≠ boundary ≠ spelling.** Identity stays the code; spelling (IAST, Devanāgarī, Cyrillic) is a view; sequence ↔ text is a separate, mechanically checked layer (see my comment on #1971).
