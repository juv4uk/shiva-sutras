# Research Index (Карта Знань)

Цей документ є актуальною мапою знань проєкту. Тут зібрані всі завершені експерименти, їхні гіпотези, методи, ключові артефакти та фінальні статуси. Цей індекс дозволяє відновити траєкторію дослідження без необхідності читати весь хронологічний журнал.

---

## 1. Топологічна свобода (C1P Admissible Space)
- **Гіпотеза (`H-SIVA-ORDER`)**: Канонічний порядок 43 звуків у Śiva-sūtras є унікальним (єдиним можливим), який дозволяє сформувати 42 необхідні множини (pratyāhāra) як безперервні відрізки.
- **Метод**: Алгоритмічний пошук усіх валідних Consecutive Ones Property (C1P) перестановок.
- **Артефакти**: `experiments/ordering/c1p_sat_ablation.py`
- **Результат**: Знайдено понад 10,000 валідних топологічних рішень. 
- **Статус**: 🔴 **СПРОСТОВАНО**
- **Висновки**: Сама лише вимога безперервності (Level 1) не пояснює унікальність канонічного порядку.

## 2. Оптимізація Адресації (The Addressing Problem)
- **Гіпотеза (`H-SIVA-MARKERS`)**: Канонічний порядок обраний серед тисяч можливих, оскільки він мінімізує кількість `it`-маркерів (boundaries), необхідних для адресації 42 множин.
- **Метод**: CP-SAT вирішувач, математичне доведення глобального мінімуму, The 10,000 Test (ранжування альтернатив).
- **Артефакти**: `experiments/ordering/marker_analyzer.py`, `experiments/ordering/marker_optimizer.py`
- **Результат**: Математично доведено стан `UNSAT` для $M \le 13$. Абсолютний глобальний мінімум становить $14$ маркерів. Канонічний порядок досягає цього абсолютного оптимуму.
- **Статус**: 🟢 **ПІДТВЕРДЖЕНО (Математичний доказ)**
- **Висновки**: 14 сутр — це не естетичний вибір, а доведений структурний мінімум для 42-класової моделі.

## 3. Семантика Імен та Кістяк Складності (Address Semantics Fingerprint)
- **Гіпотеза**: Із 23,737 знайдених топологій, що досягають $M=14$, канонічна структура (де `e, o` передують `ai, au`) є єдиною, що підтримує традиційні імена пратяхар без колізій.
- **Метод**: Аналіз MUC (Minimal Unsatisfiable Core), перевірка імен пратяхар (*Ādir antyena sahetā*).
- **Артефакти**: `journal/0001-methodology-shift.yaml`, `walkthrough.md`
- **Результат**: Альтернативний клас структур (Class A) неминуче генерує фатальну колізію імен (напр., пратяхара `aic` адресує одночасно дві різні множини). Канонічний Class B не має колізій і відображає природну градацію аблаута (guṇa $\rightarrow$ vṛddhi).
- **Статус**: 🟢 **ПІДТВЕРДЖЕНО**
- **Висновки**: Останній ступінь топологічної свободи закритий семантичними та фонологічними обмеженнями.

## 4. Виявлення Кандидатів (High-Recall Annotation)
- **Гіпотеза**: Можливо автоматично відсіяти нефонологічні правила Aṣṭādhyāyī (із 3983 сутр), не спираючись на готові традиційні класифікації, використовуючи лише структурні тригери.
- **Метод**: Багатоітераційний лексичний, token-aware та shape-condition аналізатор (Stratified Audit).
- **Артефакти**: `ksetra/astadhyayi/blind/` (результати)
- **Результат**: З початкових 3983 сутр класифіковано 492 як `YES`, 1220 як `MAYBE`, і 2271 як `NO` (відсіяні).
- **Статус**: 🟡 **ЗАВЕРШЕНО (Заморожено)**
- **Висновки**: Створено чистий, ізольований від "апріорних знань" пул кандидатів для сліпої реконструкції (Stage 6.0).

## 5. Епістемічний Бар'єр: Відтворюваність vs Автентичність
- **Гіпотеза**: Автоматичний колектор може збирати "зовнішні" докази (Evidence Layer) і сам засвідчувати їхню історичну справжність (Authenticity).
- **Метод**: Архітектурна ізоляція Collector $\rightarrow$ Authenticator, криптографічна перевірка SHA-256.
- **Артефакти**: `experiments/blind_reconstruction/source_collector.py`, `experiments/blind_reconstruction/source_authenticator.py`, `experiments/blind_reconstruction/validator_v2.py`
- **Результат**: Виявлено фатальну архітектурну ваду: об'єкт не може засвідчувати власну істинність. Система довела відтворюваність своєї ж галюцинації. 
- **Статус**: 🔴 **СПРОСТОВАНО (Новий Методологічний Принцип)**
- **Висновки**: `Reproducibility ≠ Authenticity`. Артефакт повинен мати незалежні осі перевірки. Корпус чесно замаркований як `AUTHENTICITY-UNVERIFIED`.

## 6. Експертний Виграш (Synthetic Evidence Expert Gain)
- **Гіпотеза**: Автоматизований семантичний пайплайн ($B_2^{automatic}$) схильний перетворювати припущення на "знання" там, де локальний текст джерела містить недостатньо доказів. Експертна ад'юдикація ($B_2^{expert}$) здатна відновити епістемічну межу.
- **Метод**: Подвійне сліпе тестування (Blind Adjudication) на 30 сутрах, розрахунок False Certainty Rate (FCR) та $EG_{epistemic}$.
- **Артефакти**: `experiments/blind_reconstruction/compare_auto_expert.py`, `experiments/blind_reconstruction/reports/batch_2_synthetic_expert_gain_report.md`
- **Результат**: FCR = 83.3%. У 25 із 30 випадків автоматика помилково призначила `RESOLVED`. Експерт відновив статус `REVIEWED` (`UNRESOLVED-BY-EVIDENCE`).
- **Статус**: 🟢 **ПІДТВЕРДЖЕНО**
- **Висновки**: Принцип "негативний результат = досліджена територія" успішно діє. Експертиза довела свою необхідність навіть на синтетичному (проте строго відтворюваному) корпусі.

## 7. GRETIL Corpus Gate (Реальні джерела з Provenance)
- **Гіпотеза (`L-002`)**: Доступний незалежний, достовірний корпус Kāśikā/Aṣṭādhyāyī з підтвердженим походженням.
- **Метод**: Завантаження двох незалежних GRETIL-свідків (Kāśikāvṛtti Sharma ed. `jvkasipu.htm` + Aṣṭādhyāyī Baums `panini_u.htm`), фіксація sha256/URL/редакції у `external_data/gretil_raw/manifest.json`, крос-порівняння свідків, генерація source-файлів зі статусом `REAL`.
- **Артефакти**: `experiments/blind_reconstruction/fetch_gretil_corpus.py`, `parse_gretil.py`, `cross_witness_diff.py`, `generate_real_sources.py`; `reports/cross_witness_gretil_diff.md`
- **Результат**: Розпарсовано 3951 сутра Kāśikā (sūtra + commentary) та 3958 сутр Aṣṭādhyāyī. Крос-порівняння (вирівнювання послідовностей): 1891 AGREES / 2013 VARIANTS (конвенції транскрипції) / 22 CONFLICTS / 57 MISSING. Сгенеровано 3951 source-файл `REAL` для сутр, згаданих у blind-пайплайні. Черга ад'юдикації 22 конфліктів — `reports/conflicts_adjudication.md`.
- **Статус**: 🟢 **ВИРІШЕНО** (`AUTHENTICITY-VERIFIED (Attributed)`)
- **Висновки**: Гейт L-002 пройдено. Редакційні розбіжності (1.1.46–75, 8.3.118–119, 2.4.27) задокументовано; для них `REAL` не призначається без ад'юдикації критичним виданням. Фіктивну заявку про `verified_ashtadhyayi.txt` видалено (False Certainty).

## 8. Координація з Downstream (Epistemic Coordination Contract)
- **Гіпотеза**: `shiva-sutras` виступає upstream-епістемічним авторитетом і координується з downstream-проєктами (зокрема `my-lisp-panini`) через версіоновані твердження, а не через архітектурні поради.
- **Метод**: Контракт із 10 правил: authoritative scope, заборона downstream-гіпотез як premises, експорт claims (не порад), обов'язковий `scope`, заборона дублювання онтології, двостороння видимість залежностей, upstream impact signals, незмінність epistemic status, експорт негативних результатів, категорія `question-origin` для downstream-питань.
- **Артефакти**: `docs/epistemic-coordination.md` (повний контракт + claim API у Scheme-форматі), `.agents/rules/epistemic_agent.md` (upstream-роль агента).
- **Результат**: Встановлено формат claims `(claim (id ...) (owner ...) (status ...) (scope ...) (evidence ...) (revision ...))` та механізм `DOWNSTREAM IMPACT` сигналів при зміні статусу.
- **Статус**: 🟢 **КОНТРАКТ** (постійний протокол координації)
- **Висновки**: Відносини репозиторіїв організовано як "package manager для знань": downstream може імпортувати `(depends-on "SS-..." :min-status 'supported)` і одразу бачити втрату основи при зміні upstream-статусу.
