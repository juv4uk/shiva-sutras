# Програма дослідження Śiva-sūtras

## 0. Головне правило агента

Перед усіма іншими інструкціями:

> **Ти дослідник, а не знавець.**
>
> Не намагайся підтвердити нашу гіпотезу про Śabda.
> Не намагайся довести, що Śiva-sūtras є «давнім машинним кодуванням».
> Не оптимізуй їх під FPGA.
> Не перекладай Паніні мовою сучасної computer science.
>
> Твоє завдання — зменшувати область невідомого.

Якщо дослідження покаже, що якась наша красива гіпотеза неправильна, це **успішний результат дослідження**.

---

# I. Зафіксувати Kṣetra
Перший етап взагалі не повинен нічого «винаходити». Агент створює карту того, що ми досліджуємо.
Ці шари **ніколи не змішуються**:
- CANON: 14 sūtras, sequence, markers
- PĀṆINIAN FORMAL USE: pratyāhāra construction, occurrence resolution, actual use in Aṣṭādhyāyī
- TRADITIONAL INTERPRETATION
- MODERN SCHOLARSHIP
- OUR HYPOTHESES
- ENGINEERING

---

# II. Встановити сам канон
Агент повинен провести окреме джерелознавче дослідження.
Питання: **Які найдавніші доступні свідчення саме цього порядку?**
Треба простежити від манускриптів до сучасних видань. Для кожної одиниці: claim, source, date, confidence тощо.

---

# III. Не починати з фонетики — починати з функції
Дослідити всі фактичні використання pratyāhāra в Aṣṭādhyāyī.
Для кожного: sūtra -> pratyāhāra -> множина -> навіщо потрібна -> результат.

---

# IV. Відновити механіку pratyāhāra без сучасних аналогій
Формально відтворити без слів: bitmap, opcode, type, regex, token class.
Спочатку лише: канон → операція → результат.

---

# V. Дослідити, ЧОМУ порядок саме такий
Експериментально переставляти звуки (random, phonetic, alphabetic) і вимірювати:
- скільки потрібних класів можна компактно виразити
- які класи стають неможливими
- яка середня довжина
Питати: **«За якою функцією вони незвичайні?»**

---

# VI. Adversarial Śiva Test
Окремий агент отримує протилежне завдання: **Доведи, що в Śiva-sūtras немає нічого обчислювально особливого.**
Шукати простіші пояснення (мнемоніка, педагогіка тощо). Атакувати наші гіпотези.

---

# VII. Immutable Research Journal
Кожен експеримент чи питання фіксується (hypothesis, question, method, conditions, result, timestamp) незалежно від того, успішний він чи ні.
Негативний результат освітлює територію лише відносно поставленого питання.

---

# VIII. Агент повинен шукати не лише відповіді, а нові питання
Після кожного циклу агент має створити: NEW QUESTIONS. 
Наприклад: «Чому певні звуки ніколи не використовуються як початок practically useful pratyāhāra?»

---

# IX. Тільки після цього — сучасна фонологія
Коли ми достатньо зрозуміємо внутрішню систему, підключаємо академічну фонетику. Вона **анотує**, а не переписує канон.

---

# X. Потім — інші мови
Що відбувається з механізмом Śiva-sūtras, коли фонологічний простір розширюється (українська, англійська)? Будь-який результат є цінним.

---

# XI. Śabda поки заморозити
Усі інженерні ідеї зберігати зі статусом PREMATURE-HYPOTHESIS. Вони — історія нашого мислення, але не керують дослідженням.

---

# XII. І лише в самому кінці — машинне кодування
Яке машинне представлення найкраще зберігає виявлені властивості системи? (8 bit, 16 bit, graph, set algebra).

---

## Цикл самого агента
KṢETRA (карта знань) -> вибрати UNKNOWN -> сформувати QUESTION -> створити HYPOTHESES -> знайти EVIDENCE -> TEST / COMPARE -> result (supported/rejected/unresolved) -> IMMUTABLE JOURNAL -> оновити карту -> NEW QUESTIONS GENERATED -> repeat.

**Метою агента не повинно бути підтвердження Śabda.**
Reward: **зменшуй область невідомого, не збільшуючи область необґрунтованої впевненості.**
